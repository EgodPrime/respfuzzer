## Experiment: Insert C/C++ Source Code into LLM Prompt

This experiment evaluates whether providing C/C++ source code in the LLM prompt improves the quality of generated test cases.

### Setup

```bash
cd experiments/experiment-extension-module-code

# 1. Use the original tool (solve() from agentic_function_resolver.py) to generate test cases for 25 APIs
#    Reads from manifest.json, outputs to output/respfuzz/
uv run python generate_test_cases.py

# 2. Use LLM to generate test cases WITHOUT C/C++ source context
#    Reads from manifest.json, outputs to output/llm_easy/
uv run python generate_llm_easy.py

# 3. Use LLM to generate test cases WITH C/C++ source context (via generate_llm_hard.py logic)
#    Reads from manifest.json, outputs to output/llm_hard/
#    Each API's manifest entry includes the found C/C++ source code for reference
uv run python generate_llm_hard.py

# 4. Use the original tool with C/C++ source INJECTED INTO the solve() prompt
#    Reads from manifest.json, outputs to output/respfuzz_with_source/
#    This modifies the Attempter prompt to include C/C++ source before calling LLM
uv run python generate_test_cases_with_source.py

# 5. Check syntax and runtime correctness for all generated test cases
uv run python check_syntax.py
```

### Output Directories

| Directory | Description |
|-----------|-------------|
| `output/respfuzz/` | Test cases generated by original `solve()` without C source |
| `output/llm_easy/` | Test cases generated by LLM without C source |
| `output/llm_hard/` | Test cases generated by LLM with C source (separate LLM call) |
| `output/respfuzz_with_source/` | Test cases from modified `solve()` with C source in prompt |

### Input

- `manifest.json`: Contains 25 APIs (5 per library: numpy, pandas, scipy, torch, paddle)
  - Each entry has `func_name`, `library_name`, and `source_file` (path to C/C++ source)

### Comparison

- **resp vs resp_with_source**: Original tool with/without C source in prompt
- **llm_easy vs llm_hard**: LLM-only approach without/with C source
- **llm_hard vs resp_with_source**: Different methods of using C source (separate LLM call vs injected into existing tool)
